# Spike A — vorpaljs/bash-parser as the dsh-shell-js parser

- **Date**: 2026-10-11
- **Worktree**: `/Users/lixiang/workspace/dsh-mobile-shell-js` (branch `feat/dsh-shell-js`, no commits made)
- **Candidate**: `bash-parser@0.5.0` (npm, registry metadata + tarball inspected)
- **Verdict**: **degrade** — functionally passes the whole dialect checklist and is QuickJS-syntax-safe, but it is unmaintained since 2017, drags 30 packages / 91 files (~388 KB runtime closure) including a 230 KB babylon used only for `$((...))` arithmetic, and hard-requires a `process.env` shim (or a one-line patch) because it reads `process.env.NODE_NEV` on **every parse**.

All evidence below was produced during this spike inside `tmp/shell-js-spikes/` (scratch install at `tmp/shell-js-spikes/scratch-bash-parser/`, unpacked tarball at `tmp/shell-js-spikes/pkgs/bash-parser-0.5.0/`).

## 3. Node-specific API scan (QuickJS hazards)

Full-tree grep of `process.|require('fs')|require('path')|Buffer|__dirname|child_process|setImmediate|global` over `src`:

1. **`process.env.NODE_NEV` — REAL, per-parse blocker.** `src/modes/posix/tokenizer/index.js:184`:
   ```js
   const State = process.env.NODE_NEV === 'development' ? mkImmutableState(reducers) : mkMutableState(reducers);
   ```
   This line lives in the tokenizer generator factory that `shellLexer` invokes **on every parse**. Empirically verified: with `globalThis.process = undefined`, `parse('echo hi')` fails immediately — `Error: TypeError: Cannot read properties of undefined (reading 'env')` (script `scratch-bash-parser/no-process.js`). In QuickJS, which has no `process` binding at all, this is a `ReferenceError` — same failure class. **A `globalThis.process = {env: {}}` shim or a one-line patch is mandatory.** (Also note the typo `NODE_NEV` — the immutable-state branch is effectively dead code even under Node.)
2. **`fs`/`path`/`process.argv`/`process.exit`/`console.log` in the three `built-grammar.js` files (lines 435–449)** — this is the stock Jison CLI footer, guarded by `if (typeof module !== 'undefined' && require.main === module)`. It never executes when required as a library; a CJS shim only needs `require.main` and `module` to be definable (`require.main === module` evaluates false). Dead code for our purposes.
3. **`fs`/`json5`/`node-uuid` in `src/index.js:37-41`** — inside a `/* … */` commented-out fixture-dump block. Dead.
4. **No `Buffer`, no `child_process`, no timers, no `events`, no streams, no `__dirname` at runtime** anywhere in the 91-file closure. Everything else the code touches is pure language + standard built-ins: `Object.assign`, `Array.from`, `Symbol.iterator`, `JSON`, `RegExp`, `String.fromCodePoint` (polyfilled by `string.fromcodepoint` anyway).

So the Node surface is exactly one line that matters (`process.env.NODE_NEV`) plus the CommonJS module system itself.

## 4. Behavior probe (system Node v24.14.0; script `scratch-bash-parser/probe.js`, `probe2.js`)

Default mode is `posix` (`src/index.js:25`); every case below was also re-run with `{mode: 'bash'}` — **14/14 identical pass**. Dialect checklist from the spike ask, with AST node types observed:

| # | input | result | node types |
|---|---|---|---|
| Q1 | `echo 'single quoted'` | pass | Script, Command, Word |
| Q2 | `echo "double quoted"` | pass | Script, Command, Word |
| Q3 | `echo back\ slash` | pass | Script, Command, Word (text becomes `back slash`) |
| Q4 | `echo "esc \" inside"` | pass | Script, Command, Word |
| V1 | `echo $VAR` | pass | + ParameterExpansion |
| V2 | `echo ${VAR}` | pass | + ParameterExpansion |
| V3 | `echo "${VAR}-suffix"` | pass | + ParameterExpansion (loc offsets into raw text) |
| P1 | `a \| b` | pass | Script, **Pipeline**, Command, Word |
| L1 | `a && b` | pass | Script, **LogicalExpression**(op:"and"), Command, Word |
| L2 | `a \|\| b` | pass | Script, LogicalExpression(op:"or"), Command, Word |
| L3 | `a && b \|\| c` | pass | left-associative nesting of LogicalExpression |
| S1 | `a; b` | pass | flat `Script.commands: [Command, Command]` (separator not represented) |
| R1 | `cmd > out.txt` | pass | + **Redirect**(op.type `great`, file Word) |
| R2 | `cmd >> out.txt` | pass | + Redirect(op.type `dgreat`) |
| R3 | `cmd 2> err.txt` | pass | + Redirect + `io_number: 2` |
| G1 | `ls *.js` | pass | plain Word (no glob node — pathname expansion is post-parse) |
| G2 | `ls file?.txt` | pass | plain Word |
| C1 | `echo hi # a comment` | pass | comment stripped, no node |
| C2 | `# whole line comment` + newline + `echo hi` | pass | comment stripped |

Shape notes (from full AST dumps):

- Quoting/escaping is already folded into `Word.text` (quote removal applied at parse time), while expansions survive as `Word.expansion[]` with `{type, loc: {start, end}, …}` — e.g. `echo "${VAR}-x" 'lit'` gives suffix Words `"${VAR}-x"` (with ParameterExpansion) and `lit`.
- `a | b > f` → `Pipeline{commands:[Command(a), Command(b, suffix:[Redirect(great, f)])]}` — redirect binds to the pipeline member.
- Bonus (beyond the checklist): `FOO=bar cmd arg` → `prefix: [AssignmentWord]`, `suffix: [Word]`; `echo $((1+2))` → `ArithmeticExpansion` carrying an embedded **babylon** `arithmeticAST` (`BinaryExpression/NumericLiteral`).
- Newlines separate commands the same way `;` does.
- **Error contract**: unclosed quote → `SyntaxError: Unclosed "`; grammar errors (e.g. `a | | b`, `if true; then`) → generic `Error: Parse error on line 1: Unexpected 'PIPE'/'EOF'` — because `src/index.js:48-52` rethrows `SyntaxError` untouched but wraps everything else as `new Error(err.stack || err.message)`. Callers cannot `instanceof SyntaxError` grammar failures; error matching must be on message text.

False-positive cleanups done: the `**` hits in `to-*-case` packages are JSDoc `/**` comment openers; babylon's `await`/`async`/`Promise` occurrences are keyword-table strings and contextual checks (it *parses* those tokens), though its own compiled code does use ES2015 `class`/arrow/`async function` — all within ES2023. Regex literals in the closure use at most classic flags (`g/i/m/s/u/y`-family; nothing exotic like named-group-only constructs verified beyond that).

**Conclusion**: language-wise the closure is ≤ ES2020 throughout — fully inside quickjs-ng's ES2023 support. The only QuickJS gap is environmental, not syntactic: (a) the `process.env` read (§3.1) and (b) the CommonJS module system — 30 packages/91 files that the host's existing closure-bundling path (`build/build.sh sync` + `closures` gate per BUILD.md/AGENTS.md) would need to swallow. That bundling capability is documented repo machinery; this spike did not exercise it.

## 6. Risks / caveats

1. **Unmaintained**: last release 2017-06-22 (9+ years); vorpaljs ecosystem largely dormant. Pinning is mandatory anyway (repo D6), but there will be no upstream fixes.
2. **babylon weight**: 230.7 KB (60% of closure) exercised only by `$((…))`. If arithmetic expansions are out of scope for dsh-shell-js v1, that mass is pure dead weight you still pay at load time (unconditional `require`).
3. **Error contract**: grammar failures arrive as plain `Error` (message-string matching), only the tokenizer's unclosed-quote class is a real `SyntaxError` (`src/index.js:48-52`).
4. **`process.env.NODE_NEV` typo** means the immutable/development state branch is unreachable — harmless, but signals the code's age.
5. Dialect coverage beyond the checklist was not audited (no heredocs, subshells, `for`/`while`, function defs, process substitution probes run — out of the ask's list; the grammar tables visibly contain them, but unverified here).
